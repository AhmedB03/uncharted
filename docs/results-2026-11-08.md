# Build fidelity fixes (2026-11-08)

After the v2 spec work, builds were the weak step: specs scored ~3.5 on realness, while the code
scored ~2.5 on fidelity to the spec. Reading the 22 judged v2-spec builds showed four causes:

1. **The build gate was only "the model's own tests pass".** The same model writes the code and the
   tests, so `perfblame-build` counted as built after one round with ~2.7k characters of code and
   almost every feature missing (fidelity 1). In other builds, the headline component was built but
   never used.
2. **The fixer saw only the first 40k characters.** 5 of the 8 failed builds were longer, so the
   end of the package (often the whole test file) was hidden, and full-file rewrites of half-seen
   modules broke test collection. Nothing ever undid a bad round.
3. **The file-block parser kept stray `END` lines.** Models close every file with
   `===== END =====`, and the parser left that line in all but the last file: a SyntaxError. Most
   multi-file fix rounds in every earlier run were broken by this.
4. **The judge saw only the first 30k characters.** 15 of the 22 builds were longer, so features past
   the cut were scored as missing.

## Changes

- Each entry of the spec's `tests` checklist needs its own passing `test_spec_NN_*` test before a
  build counts (`build --no-spec-gate` keeps the old rule). Missing entries go back to the model by name.
- A fix round that scores worse is undone, and a failed build keeps its best state on disk.
- The fixer sees up to 200k characters, and any truncation is marked. The build prompt asks for
  modules of ~300 lines and for every feature to be wired into the real code path.
- The parser cuts each file at its own `END` line.
- `judge --source-chars` (default 120000, package code before tests) gets its own cache file
  (`judge_src120k.json`). `--source-chars 30000` reproduces the older `judge.json` scores, and the
  spec experiment is pinned to it.

## A/B check

8 v2-spec combos (the 4 lowest-fidelity builds and 4 failed ones) were rebuilt with the same builder
(Haiku 5.5, 8 rounds). Old and new builds were judged blind by Gemini 3.8 flash at the 120k view.
Cost: ~$0.35.

| project | old fidelity / usefulness | new fidelity / usefulness |
| --- | --- | --- |
| perfblame-build | 1 / 1 | 5 / 2 |
| typed-native-plan | 1 / 1 | 5 / 3 |
| awesome-wire | 2 / 2 | 3 / 2 |
| plugpile | 3 / 2 | 5 / 3 |
| jsjobq | failed | 5 / 3 |
| linkpack | failed | 5 / 3 |
| routecast | failed | 4 / 2 |
| mdcue-player | failed | failed |

Built 7/8, versus 4/8 before. n=8, and Gemini gives higher scores than Sonnet, so read this as a
paired direction, not as absolute scores. Usefulness is still 2-3: the builds now match their specs,
but the specs themselves are small tools.
